# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

10x-standard: v1.9
10x-profile: public

## What this is

The compatibility contract for
[astl](https://github.com/arhuman/ansible-static-lint): the frozen
ansible-lint 26.8.0 corpus, the golden pep8 output over it, and one test
asserting astl reproduces that output exactly. It is a separate repository
because the corpus is GPL-3.0-or-later ansible-lint test data while astl stays
MIT.

## Rules that are easy to get wrong

- `golden/expected_extra.txt` is hand-reviewed, never regenerated. Every line
  must be explained in `PARITY.md` before it enters the file. `make regenerate`
  refuses to touch it on purpose.
- There are **two** contracts. `corpus/` is upstream's `examples/` tree and
  tolerates the reviewed extras above; `cases/` is this project's own fixtures
  and tolerates none, because a fixture is added there precisely because astl
  and ansible-lint should agree on it exactly. Never put a fixture in `corpus/`:
  `make regenerate` deletes that directory and refills it from upstream.
- The assertion is an identity, not a threshold: a missing golden line, a new
  extra, and a vanished expected extra each fail individually.
- `BENCH_BUDGET_MS` is never raised to green a red `make bench`; find what made
  the corpus slow instead.
- The harness resolves astl in two modes, and they are not interchangeable. A
  checkout (`ASTL_REPO`, default `../ansible-static-lint`) wins when present and
  is the only one that sees unreleased changes; with no checkout it installs
  `github.com/arhuman/ansible-static-lint/cmd/astl@$ASTL_VERSION` so a lone
  clone of this repo still runs. CI clones astl on purpose: a green run must
  mean astl's current tree is compatible, not that some published version was.
  `scripts/bench.sh` repeats the same resolution and must keep matching
  `check_test.go`, or the two gates would measure different binaries.

## Make targets

`make check` (both golden assertions), `make cover` (check + coverage gate),
`make audit` (cover + mod verify + golangci-lint + govulncheck, same command in
CI), `make bench`, `make regenerate`, `make regenerate-cases`, `make tidy`,
`make tools`.

Both regeneration scripts source the two files that hold what must be identical
between them: `scripts/rules.sh` for the rule filter, `scripts/upstream.sh` for
the pinned toolchain (ansible-lint, yamllint, ansible-core) and the corpus ref.
Neither golden file can end up filtered by a different list or generated by a
different version. Add any new cross-script invariant there rather than
duplicating it.

Regeneration is reproducible and must stay that way: `make regenerate` on an
unchanged pin returns a byte-identical file, so any diff is a real change. Three
things buy that, and each was a leak once. Every site that runs ansible-lint
neutralizes both the yamllint configuration and `ANSIBLE_HOME` (collections
decide what `risky-file-permissions` reports, and `--offline` does not hide what
is already on disk); the output is sorted with `LC_ALL=C`. The sites that run
astl need only the yamllint half, since astl reads no `ANSIBLE_*` variable.
